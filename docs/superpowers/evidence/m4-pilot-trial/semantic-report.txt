*Inferred from reading code (not separately proven):*
- The reason `HomePresenter.kt:14` still works despite `override val summary: String = "$count items"` being a `val` with an initializer (evaluated once per object construction, not a computed property): `HomePresenter` returns a non-`Unit` value, so Compose cannot make it a restartable scope. The `count` read therefore invalidates the enclosing scope, `AppUi.Show()`, which re-runs `HomePresenter()` and builds a fresh bindings object each recomposition. The observed increments are consistent with this, but I did not instrument recomposition to prove the mechanism.

**Caveat I deliberately did not "fix":** that `val` is a latent hazard — it reads correct only because of the non-restartable-scope detail above. `override val summary: String get() = "$count items"` would be more robustly idiomatic. I left it alone because the brief asked for a *minimal* fix and the line is empirically correct; changing working code on a theory would have been scope creep.
